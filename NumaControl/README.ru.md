# NUMA Control 1.6.1 — краткая справка

**[English](README.md) · [Русский](README.ru.md)**

NUMA Control назначает игровым процессам выбранные ядра через штатные API CPU affinity Windows. В программе есть профили, выбор физических ядер и SMT-потоков, фоновое наблюдение, трей, четыре темы и локальная диагностика. Привязка не гарантирует рост FPS: сравнивайте время кадра и стабильность в своих играх.

> **Предупреждение об античитах:** Проверено только с Valve Anti-Cheat (VAC). Совместимость с другими античитами не проверялась и не подтверждена. Проверка с VAC не является сертификацией или гарантией отсутствия ограничений со стороны игры. Перед использованием средств изменения привязки или приоритета процессов ознакомьтесь с правилами игры.

NUMA Control использует штатные Windows API для получения сведений о процессах и изменения CPU affinity ([SetProcessAffinityMask](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setprocessaffinitymask)), а при включённой опции — приоритета ([SetPriorityClass](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setpriorityclass)). Программа не внедряет DLL или код, не читает и не изменяет игровую память, не исправляет файлы игры и не обходит античит. Для этих операций Windows она открывает дескрипторы процессов; это не означает одобрения со стороны разработчика античита.

## Установка и запуск

Требуются Windows 10/11 x64, .NET Framework 4.8 и одна группа из 1–64 логических ЦП.

- **Рекомендуемый setup:** `NUMA-Control-1.6.1-setup-x64.exe` определяет .NET Framework 4.8 или новее. При отсутствии скачивает официальный компонент Microsoft и устанавливает его перед приложением. Для runtime могут понадобиться Интернет, подтверждение администратора и перезагрузка. Имеющаяся 4.8/4.8.1 пропускается; общий .NET при удалении программы сохраняется.
- **MSI:** `NUMA-Control-1.6.1-setup-x64.msi` устанавливает программу для текущего пользователя, обычно в `%LOCALAPPDATA%\Programs\NUMA Control`. Требует уже установленный .NET. Обновление, восстановление и удаление обслуживает Windows Installer, сохраняя пользовательскую папку `data`.
- **Portable:** полностью распакуйте `NUMA-Control-1.6.1-portable-x64.zip` в постоянную доступную для записи папку. Сохраните `NUMA-Control.exe.config` рядом с EXE и запустите `Open-NUMA.cmd` или `NUMA-Control.exe`.

Программа и дистрибутивы пока не подписаны доверенным сертификатом. Сверьте SHA-256 скачанного файла с `SHA256SUMS.txt` того же релиза. Не отключайте защиту Windows для обхода корпоративной политики.

## Выбор языка

Откройте **Настройки → Язык интерфейса → Русский / English**. В английском интерфейсе это **Settings → Interface language**. Изменение применяется сразу и сохраняется после перезапуска. Для прежних профилей начальным остаётся русский. Имена, пути и старый журнал не меняются; системные диалоги могут использовать язык Windows.

## Первая игра

1. Нажмите **Добавить игру**, выберите настоящий EXE игры либо запущенный процесс.
2. Укажите название. Для общего имени вроде `Game.exe` задайте точный путь, чтобы различать игры.
3. Выберите разрешённые логические ЦП и сохраните привязку.
4. Включите **Следить**, затем запустите игру обычным способом или кнопкой **Запустить игру**.
5. Проверьте состояние ожидания, применения или ошибки и при необходимости исправьте профиль.

Примеры: `cs2.exe`, `dota2.exe`, `Game.exe`. Для запуска Steam подходят `steam://rungameid/730` и `steam://rungameid/570`; также поддерживается `astrumplay://play/0.1177`. EXE для сопоставления игры и цель запуска — разные поля. Произвольные команды оболочки запрещены.

## Пресеты ЦП

| Пресет | Выбор |
|---|---|
| Все ЦП | Все активные логические процессоры |
| Без крайних ядер | Исключает первое и последнее физическое ядро вместе с SMT-потоками; при двух и менее физических ядрах оставляет все ЦП |
| По главному потоку на ядро | Первый логический ЦП каждого физического ядра по нумерации Windows; SMT-соседи не ранжируются, SMT для системы не отключается |

После любого пресета можно выбрать отдельные потоки кликами. Пустые и несовместимые маски запрещены. Новые профили исключают крайние физические ядра, если их больше двух; прежние пользовательские маски сохраняются. Нумерация логических ЦП берётся из Windows, группировка — из определённой физической топологии.

**Пауза, выход, выключение наблюдения и удаление профиля сохраняют уже назначенную игровую маску до завершения процесса.** Для явного расширения маски работающей игры примените «Все ЦП». Windows, драйверы и другие процессы за исключёнными ядрами не закрепляются.

Контроллер выбирает свои ядра вне фактических масок запущенных игр. Физическое ядро считается занятым, если хотя бы один его SMT-поток доступен игре. Когда свободных ядер нет, используется последнее физическое ядро с явным указанием пересечения. После закрытия последней известной игры восстанавливается исходная привязка самого контроллера.

## Основные действия

- **Следить:** включает один профиль; общая пауза имеет приоритет.
- **Пауза / Продолжить:** управляет назначением игровых правил, сохраняя диагностику и выбор ядер контроллера.
- **Запустить игру:** включает профиль и снимает общую паузу; повторный экземпляр уже найденной игры не запускается.
- **Ярлык на рабочий стол:** создаёт ярлык по постоянному ID профиля. Переименование и изменение маски сохраняют ID; после переноса приложения ярлыки нужно пересоздать.
- **Параметры:** редактирует или удаляет профиль. Для новых профилей высокий приоритет включён; после выключения этой настройки уже назначенный приоритет сохраняется до закрытия процесса. RealTime не используется.

Закрытие окна оставляет программу в трее; для завершения выберите там **Выход**. Автозапуск включается по желанию, использует `--tray` и не повышает права. Начальный интервал — 2 секунды; в настройках доступны 1/2/5 секунд. Пустая неактивная библиотека может спать дольше; изменение настроек будит наблюдатель.

## Темы и диагностика

В настройках доступны **Стандартная**, **Windows 11 Light**, **Windows 11 Dark** и **AMI BIOS**. Оформление сохраняется и не меняет игровые правила. AMI BIOS использует серо-синие прямоугольные элементы и Consolas. Файловые диалоги оформляются Windows.

Самодиагностика показывает реальные CPU, память, дескрипторы, потоки и сигналы отклика. Для CPU нужен первый измерительный интервал; для тренда памяти — около минуты истории. Проценты относительно одного ЦП и всего компьютера имеют разные знаменатели. Отчёты остаются локальными и могут содержать пути в исключениях или хвосте журнала: прочитайте их перед передачей.

## Данные, копии и восстановление

Обычный путь — **`data` рядом с EXE**; при отсутствии записи используется `%LOCALAPPDATA%\NumaControl`. Фактический путь виден в настройках.

| Файл/папка | Содержимое |
|---|---|
| `profiles.json`, `.bak` | Профили, выбранные язык/тема, интервалы и предыдущее корректное сохранение |
| `processor.json` | Снимок топологии CPU, проверяемый по живым данным Windows при запуске |
| `watcher.log`, `.previous` | Локальный журнал с ротацией |
| `icons/` | Кэш игровых значков и вариантов значка контроллера |
| `bug-reports/` | Ручные/аварийные отчёты и отдельный маркер `last-failure.json` |
| `legacy-backup/` | Резервные копии известных старых ярлыков после перехода, если он выполнялся |

Для копии закройте программу и сохраните всю папку данных либо экспортируйте профили в настройках. Импорт проверяет файл, запрашивает подтверждение замены и ставит наблюдение на паузу. Текущие язык и тема сохраняются. Экспорт содержит пути и аргументы. Повреждённые файлы и доступные копии сохраняются отдельно перед восстановлением; проверьте приостановленную библиотеку до продолжения. Изменение CPU/топологии также вызывает паузу для проверки.

Карточка перехода появляется только при обнаружении прежнего наблюдателя или его ярлыка. Отключение отправляет штатный сигнал остановки и сохраняет известные ярлыки, не удаляя старые EXE и не включая новый автозапуск. Неизвестные цели ярлыков требуют ручной обработки.

## Ограничения и помощь

Защищённые или повышенные игровые процессы могут запрещать привязку. При необходимости используйте такие же права, предварительно завершив обычный экземпляр контроллера. Защита не обходится. Программа не внедряет DLL, не читает/меняет память игры и не заявляет сертификацию античитами.

В [полном руководстве](USER-GUIDE.ru.md) описаны все элементы, пороги диагностики и восстановление. В [GitHub Releases](https://github.com/mrPortnov/NUMA-Control/releases) находятся загрузки и описания версий; в [репозитории](https://github.com/mrPortnov/NUMA-Control) — скриншоты и история изменений.
