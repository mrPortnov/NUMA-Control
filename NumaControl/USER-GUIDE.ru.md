# NUMA Control 1.7.2 — руководство пользователя

**[English](USER-GUIDE.md) · [Русский](USER-GUIDE.ru.md)**

NUMA Control назначает выбранные логические процессоры Windows игровым процессам и повторно применяет правило при необходимости. Один контроллер в трее управляет профилями, выбирает собственные ядра и следит за своим состоянием. Программа не управляет NUMA-памятью, не отключает SMT в прошивке и не резервирует ядра для Windows. Прирост FPS и снижение задержки не гарантируются: сравнивайте время кадра и стабильность в своих играх.

> **Предупреждение об античитах:** Проверено только с Valve Anti-Cheat (VAC). Совместимость с другими античитами не проверялась и не подтверждена. Проверка с VAC не является сертификацией или гарантией отсутствия ограничений со стороны игры. Перед использованием средств изменения привязки или приоритета процессов ознакомьтесь с правилами игры.

NUMA Control использует штатные Windows API для получения сведений о процессах и изменения CPU affinity ([SetProcessAffinityMask](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setprocessaffinitymask)), а при включённой опции — приоритета ([SetPriorityClass](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setpriorityclass)). Программа не внедряет DLL или код, не читает и не изменяет игровую память, не исправляет файлы игры и не обходит античит. Для этих операций Windows она открывает дескрипторы процессов; это не означает одобрения со стороны разработчика античита.

## Требования и установка

Нужны **Windows 10/11 x64**, **.NET Framework 4.8** и **одна группа из 1–64 логических процессоров**. Современный .NET SDK, Python, Node и исходники для обычного запуска не требуются. Назначение игровых масок на системах с несколькими группами процессоров не поддерживается.

Скачивайте файлы из [GitHub Releases](https://github.com/mrPortnov/NUMA-Control/releases). Используйте один вариант распространения за раз.

| Вариант | Установка |
|---|---|
| `NUMA-Control-1.7.2-setup-x64.exe` | Рекомендуемый. Определяет .NET Framework 4.8 или новее; при отсутствии скачивает официальный веб-установщик Microsoft и устанавливает компонент перед MSI приложения. Для runtime могут понадобиться Интернет, подтверждение администратора и перезагрузка. Имеющаяся 4.8/4.8.1 пропускается. |
| `NUMA-Control-1.7.2-setup-x64.msi` | Установка программы для текущего пользователя. Требует уже установленный .NET и не скачивает его. Стандартная папка — `%LOCALAPPDATA%\Programs\NUMA Control`. Создаёт ярлыки меню «Пуск»; ярлык программы на рабочем столе необязателен. |
| `NUMA-Control-1.7.2-portable-x64.zip` | Полностью распакуйте архив в постоянную доступную для записи папку. Сохраните `NUMA-Control.exe.config` рядом с EXE. Запустите `Open-NUMA.cmd` или `NUMA-Control.exe` вне ZIP. |

Приложение, setup EXE и MSI пока не имеют доверенной цифровой подписи. Сравните скачанные файлы с `SHA256SUMS.txt` того же релиза; внутри portable ZIP также есть пофайловый `SHA256.txt`. Контрольная сумма проверяет целостность, но не удостоверяет издателя. Соблюдайте ограничения защиты Windows и организации.

Перед обновлением, восстановлением, переносом или удалением закройте программу через трей. Для обновления используйте тот же тип пакета, что и при установке. После установки через setup.exe удаление доступно через запись NUMA Control в разделе **Параметры Windows → Приложения**. Отдельный MSI также добавляет ярлык удаления в меню «Пуск» и поддерживает восстановление через Windows Installer. Удаляются файлы программы и её ярлыки, включая распознанные ярлыки автозапуска и игр. Папка `data` и общий .NET сохраняются.

Для переноса portable перемещайте всю папку вместе с `data`. Для перехода с portable на MSI закройте обе копии, сделайте резервную копию `data`, затем перенесите её в папку установки либо используйте экспорт/импорт профилей. После импорта значки игр будут найдены заново. Пересоздайте автозапуск и игровые ярлыки для нового пути. Не запускайте одновременно разные копии с отдельными библиотеками.

## Запуск, скрытие и выход

| Действие | Результат |
|---|---|
| Открыть EXE или portable-файл `Open-NUMA.cmd` | Запускает наблюдение и открывает библиотеку; уже работающий экземпляр получает команду. CMD только открывает EXE. |
| `--show` | Явно открывает окно. |
| `--tray` | Запускает без открытия окна; используется автозапуском Windows. |
| `--launch <ID>` | Включает профиль, снимает паузу и запускает его цель. Игровые ярлыки используют постоянный ID профиля. |
| Двойной щелчок по значку трея | Открывает существующее окно или создаёт его заново. |
| Свернуть | Убирает окно в трей; несохранённый выбор ЦП остаётся в скрытом окне. |
| Развернуть | Увеличивает окно; повторное нажатие восстанавливает размер. |
| Закрыть окно | Освобождает интерфейс и продолжает работу в трее; сначала спрашивает о несохранённом выборе ЦП. |
| Меню трея → Выход | Полностью останавливает контроллер. Уже назначенные маски игр остаются до завершения их процессов. |

Библиотеки WPF/.NET могут оставаться загруженными после закрытия окна. При повторном открытии сохраняются выбранная игра и раздел в пределах текущего запуска. Автозапуск Windows включается только по выбору пользователя.

## Язык и навигация

Выберите **Настройки → Язык интерфейса → Русский / English**. В английском интерфейсе — **Settings → Interface language**. Изменение сразу обновляет страницы, редакторы, диалоги, подсказки, диагностику и меню трея и сохраняется после перезапуска. Для существующих данных начальный язык — русский. Пользовательские названия, пути и прежние записи журнала остаются как введены. Системные файловые диалоги и ошибки могут использовать язык Windows.

| Элемент | Назначение |
|---|---|
| Список игр | Выбирает профиль и показывает его состояние. Полное сокращённое название видно в подсказке. |
| Добавить игру | Открывает редактор профиля. Новая библиотека пуста. |
| Библиотека | Выбранная игра, её состояние и карта ЦП. |
| Настройки | Язык, темы, автозапуск, опрос, перенос профилей, сведения о CPU и папке данных. |
| Журнал событий | Недавние обнаружения, назначения масок, изменения настроек и ошибки. |
| Самодиагностика | Ресурсы, ядра контроллера, отклик и действия с отчётами. |
| Пауза / Продолжить | Останавливает/возобновляет назначение игровых масок и приоритетов. Самоконтроль и выбор собственных ядер продолжаются. После аварии «Продолжить» также подтверждает восстановление и очищает маркер аварии. |
| Нижняя строка состояния | Показывает результат последнего действия примерно пять секунд; новое действие начинает отсчёт заново. Длинный текст доступен в подсказке, пока сообщение видно. |

Верхние карточки показывают включённые наблюдатели, физическую/логическую топологию CPU и **ядра самого контроллера**. Число процессов игры означает процессы, к которым удалось применить правило, а не число установленных игр. Состояние контроллера — «Автовыбор» до запуска игры, «Отдельные ядра» при наличии свободных физических ядер или «Общее ядро» при резерве на последнем физическом ядре. Подсказки содержат номера ЦП и причину выбора.

Топология определяется заново через Windows при каждом запуске и записывается в `processor.json`. Сохранённый снимок не подменяет определение. При изменении CPU/топологии существующие маски сохраняются, но наблюдение ставится на паузу для проверки.

Значки берутся из локальных EXE или зарегистрированных локально значков Steam и кэшируются в `data\icons`. Если значок отсутствует или недоступен, показываются инициалы; профили продолжают работать. Изображения не скачиваются.

Tab/Shift+Tab перемещают фокус, пробел нажимает кнопки/переключатели, Enter выбирает основное действие диалога, Escape отменяет там, где это предусмотрено. Длинные страницы поддерживают колесо, полосу прокрутки и Page Up/Page Down.

## Карточка игры и запуск

| Элемент | Поведение |
|---|---|
| Название и процесс | Идентифицирует профиль и поиск по имени либо точному пути. |
| Следить | Включает/выключает правило; общая пауза имеет приоритет. При ошибке сохранения возвращается сохранённое состояние переключателя. |
| Состояние | Ожидание, назначение, пауза, PID или ошибка доступа. |
| Запустить игру | Включает профиль и снимает общую паузу. Остальные включённые профили тоже возобновляются. Уже запущенная подходящая игра повторно не запускается. |
| Ярлык на рабочий стол | Создаёт/обновляет `.lnk` с постоянным ID профиля. Разные профили с одинаковым названием получают отдельные ярлыки. |
| Параметры | Изменяет или удаляет профиль. |

Отсутствующая цель или недоступный лаунчер вызывают сообщение; наблюдение остаётся включённым и обнаружит обычный запуск через лаунчер. Переименование профиля и изменение маски сохраняют ID и ярлык. Удаление профиля делает ярлык недействительным. После перемещения контроллера ярлыки нужно пересоздать.

Наблюдаемый **EXE игры** и **цель запуска** задаются отдельно. Например, можно наблюдать `cs2.exe` и запускать `steam://rungameid/730`. Для распространённых имён указывайте точный путь игры. Поддерживаются полные пути к EXE и игровые ссылки Steam, Astrum, Epic Games, Battle.net и Ubisoft Connect.

При прямом запуске игра может получить маску сразу. Импортированные ярлыки и ссылки Epic Games, Battle.net и Ubisoft Connect передаются оболочке Windows. Наблюдатель проверяет игровой процесс после его появления и указывает, какую операцию запретила Windows.

### Игры из лаунчеров

1. Создайте в лаунчере ярлык игры на рабочем столе. В NUMA Control выберите EXE самой игры.
2. Нажмите **Взять цель из ярлыка**, откройте `.lnk` или `.url` и проверьте цель и аргументы перед сохранением.
3. Нажмите **Запустить игру**. Если Battle.net или другой клиент открыл страницу игры, нажмите в нём **Играть**. Наблюдатель дождётся игрового процесса.

#### Пример: Fortnite

1. Откройте Fortnite из Epic и выберите `FortniteClient-Win64-Shipping.exe` в меню **Добавить игру → Из запущенных процессов**. Если игра закрыта, укажите тот же файл кнопкой **Выбрать файл .exe**.
2. Нажмите **Взять цель из ярлыка**, импортируйте ярлык, созданный в Epic, и нажмите **Сохранить игру**. Чтобы добавить ярлык к существующему профилю, откройте его **Параметры**. [Как создать ярлык игры в Epic Games](https://www.epicgames.com/help/c-32735058/c-36403860/a20183292)
3. В библиотеке отметьте нужные ЦП и нажмите **Сохранить привязку**. Включите **Следить** и снимите общую паузу, если она включена.
4. Запустите игру из Epic или кнопкой **Запустить игру** после импорта ярлыка.

Наведите указатель на **ⓘ** рядом с картой процессора в **Библиотеке**, чтобы узнать режим профиля. Жёсткая маска ограничивает, на каких ЦП процесс может выполняться. Для Fortnite NUMA Control использует **Windows CPU Sets**, чтобы задать ЦП по умолчанию для потоков без собственного назначения. Диспетчер задач при этом может показывать все ЦП в жёсткой маске игры. Если жёсткая маска ограничивает выбор CPU Sets, Windows отдаёт приоритет маске. [Документация Microsoft о CPU Sets](https://learn.microsoft.com/en-us/windows/win32/procthread/cpu-sets)

Статус **Правило применено** подтверждает успешное применение. В карточке игры указано, если использовались CPU Sets. Если **Нужна проверка** подтверждает CPU Sets и показывает ошибку назначения высокого приоритета, выбор ЦП применён, а запрос приоритета отклонён. Чтобы настраивать только ЦП, выключите **Высокий приоритет процесса игры** в параметрах профиля. Чтобы расширить выбор, нажмите **Все ЦП → Сохранить привязку** при включённом наблюдении.

См. [инструкцию со скриншотами](https://github.com/mrPortnov/NUMA-Control/blob/main/README.ru.md), раздел **Первая игра**.

## Карта ЦП и сохранённые маски

Числа от нуля — **номера логических процессоров Windows**. Группы объединяют SMT-потоки обнаруженного физического ядра. Для гибридных CPU классы эффективности берутся из Windows. Метки физических ядер упорядочены по младшему логическому процессору и не являются постоянными ID BIOS.

Подсвеченные ЦП выбраны для игры. Нажатие меняет черновик, шестнадцатеричное значение и число выбранных ЦП. Шестнадцатеричное значение показывает выбор в обоих режимах.

| Пресет | Выбор |
|---|---|
| Все ЦП | Все активные логические процессоры. Контроллеру тогда может потребоваться общее с игрой последнее физическое ядро. |
| Без крайних ядер | Исключает первое и последнее физическое ядро со всеми SMT-потоками; при двух и менее физических ядрах оставляет все ЦП. |
| По главному потоку на ядро | Первый логический процессор Windows каждого физического ядра. Не ранжирует SMT-потоки и не отключает SMT во всей системе. |

Любой пресет можно поправить вручную. Новые профили используют вариант без крайних ядер, если физических ядер больше двух; существующие маски сохраняются. Сохранение недоступно без изменений, при пустом выборе или неподдерживаемой топологии. Пустые/несовместимые маски отклоняются. Сохранение на паузе или с выключенным «Следить» записывает маску; применение ждёт включения наблюдения.

При уходе с изменённого выбора программа предлагает сохранить, отбросить изменения или отменить переход. Ошибка записи сохраняет черновик. **Пауза, выключение «Следить», удаление профиля и выход не отменяют уже назначенную игре маску.** Чтобы расширить маску работающей игры, явно примените «Все ЦП» при включённом наблюдении либо перезапустите игру. Исключённые ядра не резервируются для Windows, драйверов или других процессов.

### Ядра самого контроллера

Контроллер использует объединение **фактических** масок запущенных известных игр. Если игре доступен хотя бы один SMT-поток, всё физическое ядро считается занятым. Контроллер выбирает все потоки оставшихся свободных физических ядер. Если их нет, использует последнее физическое ядро и сообщает о пересечении. Выбор основан на разрешённых масках, а не процентах загрузки.

Фактические маски читаются и при паузе/выключенных правилах; для недоступных защищённых процессов используется имеющаяся резервная информация. После удаления профиля игровое правило перестаёт назначаться, но известная запущенная игра может учитываться при выборе ядер контроллера до завершения. После закрытия последней известной игры восстанавливается первоначальная маска самого контроллера.

## Добавление и изменение профилей

Можно сохранить до **100 профилей**. Выбор ядер выполняется в библиотеке после сохранения редактора профиля.

| Поле/действие | Значение |
|---|---|
| Название | До 80 символов. |
| Имя процесса | Имя исполняемого файла без `.exe` и папки; выбор файла/процесса заполняет его автоматически. |
| Точный путь к EXE игры | Дополнительная проверка. Пустое поле означает поиск по имени; для распространённых имён рекомендуется путь. |
| Цель запуска | Полный путь к EXE или поддерживаемая ссылка. Пустая цель использует путь игры. Выбор лаунчера не меняет наблюдаемую игру. |
| Аргументы запуска | Используются только для EXE. До 4 096 символов. |
| Высокий приоритет процесса игры | Запрашивает High через API Windows. Включён у новых профилей; старые без этого поля сохраняют прежнее поведение. RealTime не используется. |
| Автоматически следить | Начальное/текущее значение переключателя «Следить». |
| Сохранить игру / Enter | Проверяет поля, пересекающиеся правила и запись на диск. При ошибке редактор и введённые данные остаются открытыми. |
| Отмена / Escape / крестик | Отбрасывает изменения редактора. |
| Удалить профиль | Требует подтверждения; удаляет запись библиотеки, оставляя игровые файлы и существующие ярлыки. Отмена сохраняет редактор. |

Два профиля с одним именем процесса требуют разных точных путей. Пересекающиеся правила имени/пути отклоняются, чтобы исключить конкурирующие назначения.

Высокий приоритет может ухудшать отзывчивость других приложений при нагрузке и не гарантирует роста FPS. Его отключение, пауза или выключение «Следить» прекращают будущие назначения; уже назначенный High остаётся до завершения процесса или ручного изменения в Диспетчере задач.

### Выбор запущенного процесса

Поиск фильтрует показанные имя, PID и доступный путь без учёта регистра. «Обновить» сохраняет фильтр, но снимает выбор. Выберите строку и нажмите «Добавить выбранный» либо дважды щёлкните; «Отмена» возвращает без изменения редактора. PID не сохраняется как правило поиска. Если защищённый путь недоступен, выберите по имени и затем укажите точный путь вручную.

Системные диалоги «Открыть/Сохранить» подтверждают путь или отменяют операцию; это не установка и не запрос повышения прав.

## Настройки и все четыре темы

| Тема | Оформление |
|---|---|
| Стандартная | Тёмно-синие поверхности и фиолетовые акценты; тема по умолчанию. |
| Стиль Windows 11 Светлая | Светлые поверхности и синие акценты. |
| Стиль Windows 11 Темная | Нейтральные тёмные поверхности и светло-синие акценты. |
| Стиль AMI BIOS | Серо-синяя палитра, прямоугольные элементы и Consolas во всём интерфейсе; мелкие подписи увеличены на один пункт. |

Сохранённая тема обновляет окна, элементы управления, навигацию, значки окна/трея/меню и ярлыков этой копии. Язык, профили и маски сохраняются. Значок EXE в Проводнике остаётся встроенным стандартным. Системные файловые диалоги оформляет Windows. Скриншоты тем есть в [русском README репозитория](https://github.com/mrPortnov/NUMA-Control/blob/main/README.ru.md#темы-оформления).

| Настройка | Поведение |
|---|---|
| Запускать вместе с Windows | Создаёт/удаляет ярлык автозагрузки текущего пользователя, вызывающий EXE напрямую с `--tray`. Повышение прав не выполняется. |
| Опрос: 1 / 2 / 5 секунд | Интервал проверки игровых процессов в ожидании и во время игры; по умолчанию 2 секунды. Старые нестандартные интервалы сохраняются до изменения. Пустая библиотека в ожидании может ждать дольше, примерно до 30 секунд; изменение будит наблюдатель. |
| Экспорт профилей | Записывает библиотеку и настройки в JSON. Содержит пути и аргументы запуска; проверьте перед передачей. |
| Импорт / восстановление | Проверяет JSON/схему, язык, маски, пересечения и доступность ЦП; спрашивает о замене, сохраняет предыдущую версию и ставит наблюдение на паузу. Текущие язык интерфейса и тема сохраняются. Можно выбрать `.bak`. |
| О программе | Версия, путь к снимку процессора и сведения о приложении. |

После переноса приложения выключите и включите автозапуск и пересоздайте игровые ярлыки. Карточка **«Предыдущее наблюдение»** появляется только при обнаружении старого наблюдателя или ярлыка автозагрузки. После подтверждения отключение отправляет штатный сигнал остановки и сохраняет распознанные ярлыки в `legacy-backup`; старые EXE не удаляются и новый автозапуск не включается. Обновление перечитывает состояние. Неизвестные цели, включая прежние PowerShell-ярлыки, требуют ручных действий средствами старого комплекта.

## Журнал событий

Показывает до 250 последних записей, новые сверху; при отсутствии записей есть пояснение. «Обновить» перечитывает журнал. Локальный файл ротируется примерно при 1 МиБ с сохранением предыдущего. В журнале могут быть пути и подробности ошибок — изучите его перед передачей.

## Самодиагностика и отчёты

Читайте показатели после сбора образцов. CPU нужен начальный интервал, тренду частной памяти — около минуты. «Обновить» перечитывает доступные значения не чаще раза в секунду, но не создаёт недостающую историю.

| Блок | Как читать |
|---|---|
| Память | Частная память, рабочий набор и управляемая память .NET в МиБ; изменение частной памяти примерно за минуту. Один положительный прирост не доказывает утечку. |
| CPU | Последний интервал примерно за пять секунд и среднее по доступной истории до примерно 30 секунд; проценты одного логического ЦП и всей машины. Ноль в простое допустим. |
| Дескрипторы и потоки | Числа дескрипторов/потоков процесса и включённых/всех профилей. |
| Ядра приложения | Выбранные ЦП, свободные физические ядра либо общее резервное ядро и причина. |
| Отклик | Возраст heartbeat UI/движка, состояние движка, последовательные ошибки, последний опрос/циклы и время работы. Возраст heartbeat не равен задержке мыши. |
| Сохранить отчёт | Создаёт ручной JSON-снимок без выхода и аварийного маркера. |
| Открыть папку отчётов | Открывает локальную папку в Проводнике; отправки нет. |

Пример CPU: 3 процессорные секунды за 5 реальных секунд — **60% одного логического ЦП**, либо **3,75% машины с 16 ЦП**. Знаменатель — полное число логических ЦП машины, а не текущая маска контроллера. Потоки могут перемещаться. Для сравнения с Диспетчером задач нужны одинаковый период и доля всей машины. Открытие окон WPF может давать короткие всплески; среднее и текущий интервал защитной политики — разные показатели.

### Автоматическая защита

Это встроенные пороги обнаружения, а не целевое потребление:

| Условие | Срабатывание |
|---|---|
| Частная память | Не менее 512 МиБ непрерывно 30 секунд. |
| Рабочий набор | Не менее 768 МиБ непрерывно 30 секунд. |
| Дескрипторы | Не менее 6 000 непрерывно 30 секунд. |
| CPU, окно скрыто | Не менее 50% одного логического ЦП в течение 60 секунд. |
| CPU, окно открыто | Не менее 90% одного логического ЦП в течение 120 секунд. |
| Heartbeat UI | Старше 45 секунд. |
| Необходимый движок наблюдения | Неожиданно остановлен либо heartbeat старше 90 секунд. |
| Повторные ошибки движка | Пять последовательных ошибок цикла. |
| Ошибка собственной маски / необработанное исключение | Критический сбой привязки контроллера либо необработанное исключение UI/трея/потока/задачи. |

Отдельная эвристика утечки использует пятиминутную историю после минутного прогрева. Она ищет рост частной памяти не менее 96 МиБ либо 2 000 дескрипторов и рост как минимум в 60% соседних образцов. Однократная загрузка WPF сама по себе не означает утечку. Изменение видимости окна перезапускает прогрев тренда; большой промежуток между образцами, например сон/пробуждение, очищает накопленные интервалы и заново запускает период сбора истории.

Обычный неверный ввод, отсутствующий EXE, отклонённый файл профилей и ожидаемые ошибки доступа/записи показывают сообщение пользователю, а не автоматически признаются отказом всей программы.

### Авария и следующий запуск

При обнаруженном критическом отказе контроллер останавливает наблюдение, пытается сохранить отчёт и `last-failure.json`, затем завершает работу. Запустите его вручную. Следующий запуск остаётся на паузе для проверки причины и профилей; «Продолжить» очищает маркер, сохраняя отчёты.

JSON ограниченного размера включает причину/исключение, сведения о приложении/Windows/CPU, маски, сводку настроек, историю ресурсов и хвост журнала. Дампа памяти, памяти игр, полного экспорта профилей и аргументов запуска в нём нет. Исключения и журнал всё равно могут содержать локальные пути и сведения о процессах. Проверяйте каждый отчёт перед отправкой.

Обычно отчёты находятся в `data\bug-reports`. Если запись невозможна, проверяются `data\recovery\<id>\bug-reports` рядом с EXE, затем `%TEMP%\NumaControl-recovery\<id>\bug-reports`. Вместе сохраняются до 20 ручных/аварийных отчётов; маркер отдельный. Обнаружение эвристическое и не покрывает все ошибки. Отключение питания, принудительное завершение или отказ диска могут помешать записи отчёта.

## Данные, резервное копирование и восстановление

По умолчанию используется **`data` рядом с EXE**; при недоступности записи — `%LOCALAPPDATA%\NumaControl`. Настройки показывают фактическое место. Первый portable-запуск может скопировать прежние данные AppData, если локальных профилей нет, сохранив оригинал.

| Файл/папка | Назначение |
|---|---|
| `profiles.json` | Профили и настройки, включая язык, тему, опрос и приоритет. |
| `profiles.json.bak` | Предыдущая корректная сохранённая конфигурация. |
| `processor.json` | Снимок топологии, определённой через Windows. |
| `watcher.log`, `watcher.log.previous` | Текущий/предыдущий журнал событий. |
| `icons/` | Локальные значки игр и варианты значка контроллера по темам. |
| `bug-reports/` | Ручные/аварийные JSON и `last-failure.json`. |
| `legacy-backup/` | Распознанные ярлыки прежнего наблюдения при миграции. |
| Копии повреждения/восстановления | Сохранённые исходные файлы при восстановлении конфигурации. |

Закройте приложение перед резервным копированием всей папки данных. При сохранении остаётся резервная копия. Повреждённый JSON сохраняется вместо молчаливой перезаписи; доступная корректная копия восстанавливается, наблюдение ставится на паузу. Если обе копии непригодны, сохраните их, восстановите/импортируйте заведомо исправную и проверьте библиотеку перед продолжением. Недоступные ЦП при импорте отклоняются; существующие маски после замены CPU можно исправить на паузе.

Программа работает без сети и не отправляет отчёты автоматически. Необязательный setup скачивает .NET, а запуск игры/URI передаётся установленному игровому клиенту с собственным сетевым поведением. Регистрация Windows Installer и явно запрошенные ярлыки автозагрузки/рабочего стола используют штатные места Windows отдельно от данных программы.

## Неполадки и безопасная передача сведений

| Проблема | Что проверить |
|---|---|
| Отказано в доступе | Игра может быть повышенной или защищённой. При необходимости закройте обычный контроллер и запустите с теми же правами. Защита может запретить доступ и администратору. |
| Несовместимая маска / новый CPU | Проверьте логические ЦП и сохраните корректную маску перед продолжением. Несколько групп процессоров не поддерживаются. |
| Цель лаунчера не открывается | Проверьте установленный клиент и импортируйте новый ярлык игры. Можно запустить игру в клиенте, пока наблюдатель ждёт процесс. |
| Ярлык перестал работать | Проверьте удаление профиля или перенос приложения и пересоздайте ярлык. |
| Неожиданное потребление ресурсов | Изучите диагностику/журнал и интервал опроса; отличайте прогрев, накладные расходы измерения интерфейса и устойчивый рост. |
| Windows блокирует пакет | Проверьте источник релиза и сумму. Smart App Control или правила организации могут блокировать неподписанное ПО; программа не меняет защиту. |

NUMA Control не внедряет DLL, не читает/изменяет память игр и не обходит античит. Совместимость с античитами не сертифицирована.

Удалите личные пути, аргументы и посторонние данные из передаваемых экспортов, журналов и отчётов. Не загружайте учётные данные, токены или личные библиотеки в публичный репозиторий.
